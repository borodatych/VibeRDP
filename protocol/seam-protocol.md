# ПРОТОКОЛ SEAM

Канал между VibeRDP на Маке и `vibe-seam-helper` на Windows: хелпер сообщает об окнах Windows, клиент показывает каждое своим окном macOS и просит хелпер действовать над окнами.
Документ каноничен: код обеих сторон следует ему, а меняется он раньше кода.
Версия протокола — **1**.

---

## 1. Канал

- Динамический виртуальный канал RDP с именем **`VibeSeam`**
- Хелпер открывает его в своей сессии: `WTSVirtualChannelOpenEx(WTS_CURRENT_SESSION, "VibeSeam", WTS_CHANNEL_OPTION_DYNAMIC)` — права администратора не нужны
- Клиент регистрирует слушателя канала при подключении; пока хелпер не открыл канал, клиент работает в режиме Desktop
- Канал двусторонний: обе стороны пишут кадры в любой момент после приветствия

---

## 2. Кадр

```
+----------------------+---------------------------+
| length: u32, LE      | body: length bytes        |
+----------------------+---------------------------+
```

- `length` — длина тела в байтах, little-endian, без самого поля длины
- Тело — одна карта MessagePack (раздел 3)
- Предел тела — **1 048 576 байт** (1 МиБ): кадр длиннее — ошибка протокола, канал закрывается
- Кадры идут подряд; канал не сохраняет границы сообщений — `WTSVirtualChannelRead` отдаёт куски, — поэтому получатель собирает кадр по длине

---

## 3. Тело

Карта MessagePack со строковыми ключами; обязательный ключ **`type`** — строка с типом сообщения.

Используется подмножество MessagePack:
nil, bool, целые (положительные и отрицательные до 64 бит), float64, str (UTF-8), bin, array, map

Правила совместимости:
- Незнакомый ключ получатель пропускает
- Незнакомый `type` получатель пропускает и пишет в журнал
- Отсутствующий необязательный ключ — значение по умолчанию из описания
- Отсутствующий обязательный ключ — сообщение пропускается и пишется в журнал; канал не закрывается

Типы значений в описаниях:
- `u32`, `u64`, `i32` — целое MessagePack в этих пределах
- `str` — строка UTF-8
- `bin` — байты
- `rect` — массив из четырёх `i32`: `[x, y, width, height]`
- `id` — `u64`, идентификатор окна: значение `HWND` на хосте

Координаты — **виртуальный экран Windows** в пикселях: главный монитор в `0,0`, как в раскладке мониторов сессии (`GetWindowRect`, `DwmGetWindowAttribute`).

---

## 4. Приветствие и версии

Первое сообщение каждой стороны — `hello`.
Хелпер шлёт его, как только открыл канал; клиент отвечает своим.

| Ключ | Тип | Смысл |
|---|---|---|
| `type` | str | `"hello"` |
| `version` | u32 | мажорная версия протокола, сейчас `1` |
| `capabilities` | array of str | что сторона умеет, раздел 5 |
| `agent` | str | имя и версия программы: `"vibe-seam-helper 0.1.0"`, `"VibeRDP 0.1.18"` |

- Разные `version` — стороны не разговаривают: клиент остаётся в Desktop и пишет в журнал
- Действует пересечение `capabilities` обеих сторон
- Клиент, не получивший `hello` за **2 секунды** после открытия канала, остаётся в Desktop без сообщений пользователю

## 5. Возможности

| Имя | Сторона | Что значит |
|---|---|---|
| `windows` | хелпер | шлёт `window.*`, `zorder`, `foreground` |
| `icons` | хелпер | шлёт `window.icon` |
| `commands` | хелпер | исполняет `command` |
| `keyboard-layout` | хелпер | исполняет `input.layout` |
| `seam` | клиент | показывает окна отдельными окнами macOS |

---

## 6. Окна: хелпер → клиент

### `window.create` и `window.update`

Окно появилось или изменилось; `update` шлёт только изменившиеся ключи, кроме `id`.

| Ключ | Тип | Обязателен | Смысл |
|---|---|---|---|
| `id` | id | да | окно |
| `owner` | id | нет | владелец: для попапов, меню, подсказок; `0` — нет |
| `rect` | rect | в `create` | видимые границы без теневой рамки: `DWMWA_EXTENDED_FRAME_BOUNDS` |
| `title` | str | нет | заголовок |
| `state` | str | нет | `"normal"`, `"minimized"`, `"maximized"`; по умолчанию `"normal"` |
| `kind` | str | нет | `"app"` — обычное окно, `"popup"` — попап, меню, подсказка; по умолчанию `"app"` |
| `pid` | u32 | нет | процесс |
| `exe` | str | нет | имя исполняемого файла без пути: `"EXCEL.EXE"` |

В список попадают видимые окна верхнего уровня, не скрытые cloak (`DWMWA_CLOAKED`), кроме `Shell_TrayWnd`, `Progman`, `WorkerW`.

### `window.destroy`

| Ключ | Тип | Смысл |
|---|---|---|
| `id` | id | окно закрылось или больше не подходит под список |

### `window.icon`

| Ключ | Тип | Смысл |
|---|---|---|
| `id` | id | окно |
| `png` | bin | иконка в PNG, до 256×256 |

### `zorder`

| Ключ | Тип | Смысл |
|---|---|---|
| `ids` | array of id | окна сверху вниз |

### `foreground`

| Ключ | Тип | Смысл |
|---|---|---|
| `id` | id | окно с фокусом на хосте; `0` — ни одно из списка |

После `hello` хелпер шлёт текущее состояние целиком: `window.create` каждого окна, `zorder`, `foreground`.

## 7. Команды: клиент → хелпер

### `command`

| Ключ | Тип | Обязателен | Смысл |
|---|---|---|---|
| `seq` | u32 | да | номер запроса, растёт с каждой командой |
| `id` | id | да | окно |
| `action` | str | да | `"activate"`, `"move"`, `"minimize"`, `"maximize"`, `"restore"`, `"close"` |
| `rect` | rect | для `move` | новые границы |

Хелпер отвечает `ack` или `error` с тем же `seq`.
- `activate` — `SetForegroundWindow`
- `move` — `SetWindowPos` с учётом теневой рамки: `rect` — видимые границы, как в `window.*`
- `minimize`, `maximize`, `restore`, `close` — `WM_SYSCOMMAND`

### `input.layout`

| Ключ | Тип | Смысл |
|---|---|---|
| `seq` | u32 | номер запроса |
| `language` | str | язык раскладки по BCP 47: `"ru-RU"`, `"en-US"` |

Хелпер шлёт окну с фокусом `WM_INPUTLANGCHANGEREQUEST` с раскладкой этого языка; окно вправе отказать — ответ всё равно `ack`, если сообщение ушло.

### `ack` и `error`

| Ключ | Тип | Смысл |
|---|---|---|
| `seq` | u32 | номер запроса |
| `code` | str | только в `error`: `"no-window"`, `"denied"`, `"unsupported"`, `"failed"` |
| `message` | str | только в `error`, необязательно: подробность для журнала |

---

## 8. Жизнь канала

### `ping` и `pong`

| Ключ | Тип | Смысл |
|---|---|---|
| `seq` | u32 | номер; `pong` повторяет номер `ping` |

- Клиент шлёт `ping` раз в **10 секунд**; нет `pong` за **30 секунд** — клиент считает хелпер пропавшим и возвращается в Desktop
- Хелпер после обрыва канала закрывает его, ждёт и открывает снова; клиент встречает его новым `hello`

---

## 9. Пример

Хелпер открыл канал и поздоровался:

```
length = 94
{ "type": "hello", "version": 1, "capabilities": ["windows", "icons", "commands", "keyboard-layout"],
  "agent": "vibe-seam-helper 0.1.0" }
```

Хелпер сообщил об окне:

```
{ "type": "window.create", "id": 132290, "rect": [120, 80, 1280, 800], "title": "Книга1 - Excel",
  "exe": "EXCEL.EXE", "pid": 7412 }
```

Клиент поднял его:

```
{ "type": "command", "seq": 1, "id": 132290, "action": "activate" }
{ "type": "ack", "seq": 1 }
```
