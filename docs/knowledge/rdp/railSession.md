# RDP: сессия RemoteApp (RAIL)

## Тип сессии выбирается при подключении

**Контекст:** таблица режимов и fallback в [idea.md](../../idea.md) §1 и §3.4; задачи 5.7 и 7.1.

**Суть:**
- Клиент заказывает RemoteApp флагом `INFO_RAIL` (0x00008000) в Info Packet (`TS_INFO_PACKET`): соединение устанавливается ради запуска удалённых программ по MS-RDPERP
- Info Packet передаётся в ходе последовательности подключения RDP, поэтому тип сессии задаётся до её начала

**Применение:**
- Откат RAIL → Seam или Desktop — новое подключение, а не переключение внутри сессии
- «Без ошибок для пользователя» из §3.4 достижимо: клиент переподключается сам, но пользователь увидит паузу на время подключения
- RAIL пробуется, только если включён в профиле, как в §3.4; фраза таблицы §1 «выбираются автоматически, в порядке приоритета» читается с этой оговоркой — иначе каждое подключение к хосту без RemoteApp стоило бы двух подключений
- Переключатель на лету из 5.7 касается только Desktop ⇄ Seam: оба режима живут в сессии рабочего стола

**Не проверено:**
- Как хост без разрешённого RemoteApp отвечает на `INFO_RAIL` — ошибкой запуска программы или разрывом; выяснить на 7.1 по MS-RDPERP и исходникам FreeRDP
