# Файлы .rdp

Сверено 2026-09-25, задача 1.6: парсер FreeRDP 3.32.0 и Info.plist установленного Windows App.
Реализация — `client-macos/Connections/RdpFile.swift`, решение 19 в [decisions.md](../../decisions.md).

## Формат и правила разбора

**Суть:**
- Строка — одна настройка `ключ:тип:значение`; тип `s` — строка, `i` — число, `b` — двоичные данные; значение может содержать двоеточия, например IPv6 в `full address:s:[fe80::1]:3390`
- mstsc сохраняет файл в UTF-16 little-endian с меткой `FF FE` и переводами строк CRLF; FreeRDP узнаёт UTF-16 только по этой метке, остальное читает как UTF-8 (`client/common/file.c:974-980`)
- Ключи FreeRDP сравнивает без учёта регистра (`_stricmp`, `file.c:380` и далее)
- `alternate full address` сильнее `full address`: так делает mstsc, и FreeRDP ему подражает (`file.c:1866-1871`); порт из адреса разбирает `freerdp_parse_hostname`, а отдельный `server port` ставится после и потому сильнее (`file.c:1873-1898`)
- Двоичные настройки вроде `password 51:b:` — пароль, зашифрованный DPAPI Windows того пользователя, который сохранил файл; на Маке он бесполезен

**Применение:** `RdpFile` читает строки и числа, двоичное пропускает; адрес в профиле — в виде редактора: порт 3389 не пишется, IPv6 — в квадратных скобках; отдельный `domain` присоединяется к имени без своего домена.

## Экран

**Суть:**
- `screen mode id:i:2` — полноэкранный режим, `1` — окно: FreeRDP ставит `Fullscreen` только при 2 (`client/common/file.c:2014-2028`), а при сохранении пишет 2 или 1 (`file.c:1192`)
- `desktopwidth` и `desktopheight` — размер рабочего стола; `dynamic resolution` — подстраивать ли его под окно (`file.c:1160-1164`, `2596`)
- mstsc сохраняет файл по умолчанию с `screen mode id:i:2` и размером своего экрана, так что большинство файлов открывает сессию во весь экран

**Применение:** импорт берёт режим экрана профиля: 2 — «Во весь экран»; `dynamic resolution:i:0` вместе с обоими размерами — «Фиксированный размер» этого размера в пределах протокола, ширина чётная; остальное — «По окну»; размер из файла сохраняется в профиле и для других режимов — [решение 39](../../decisions.md).

## Тип файла в macOS

**Суть:**
- Windows App экспортирует тип `com.microsoft.uti.rdpfile` с расширением `rdp` и MIME `application/x-rdp`, без `UTTypeConformsTo`, и открывает такие файлы с рангом `Owner`
- Без соответствия `public.data` тип Windows App не находит `UTType(filenameExtension: "rdp")`: у этого поиска по умолчанию `conformingTo: .data`, и он возвращает динамический тип `dyn.…`
- Экспорт другого приложения сильнее импорта: пока Windows App установлен, соответствие из импорта VibeRDP не действует
- Launch Services знает типы только зарегистрированных приложений: сборка в DerivedData, которую запускают тесты, своего импорта системе не объявляет

**Применение:**
- VibeRDP импортирует тот же идентификатор с соответствием `public.data`, открывает файлы с рангом `Alternate`, а панель выбора файлов фильтрует по `UTType.rdpFile`
- Тест сверяет объявление в Info.plist, а не ответ Launch Services: иначе результат зависел бы от того, стоит ли на машине Windows App
- Info.plist сборки — сгенерированный Xcode плюс `client-macos/Info.plist`: у типа документа нет настройки сборки, и Xcode сливает два файла
