# macOS: место окна между запусками

Проверено 2026-09-26 на двух экранах владельца (ZEUSLAP 1920×1200 и MateView 3008×2005 точек), решение 43.
Реализация — `client-macos/App/WindowPlacement.swift` (`WindowFrameKeeper`); тесты — `WindowPlacementTests`.

## Автосохранение AppKit переносит окно на главный экран

**Суть:**
- `setFrameAutosaveName` пишет рамку вместе со свободной областью экрана: `"x y w h sx sy sw sh"`
- Если свободная область экрана с тех пор изменилась хоть на точку — сдвинулся Dock, строка меню, — AppKit считает экран пропавшим и ставит окно на главный
- `NSWindowController` держит своё имя автосохранения и сдвигает окно каскадом, если `shouldCascadeWindows` не выключен

**Применение:** рамку хранит `WindowFrameKeeper` сам, одну, под `window.<имя>.frame`, и возвращает как есть, если полоса заголовка лежит на любом экране.

## Система переносит новое окно при запуске из Dock и Finder

**Суть:**
- Запущенное из Dock или Finder приложение показывает окно, а macOS через мгновение переносит его на дисплей, который считает текущим, в левый верхний угол — рамка окна при этом верная
- Запуск через `open` из терминала этого не делает — проверка из терминала обманывает
- Журнал 0.1.13: `opens: kept {{-2014, 1077}…}`, затем `shown: {{0, 539}…} on ZEUSLAP`

**Применение:**
- Хранитель помнит место открытия и ставит окно обратно в `applicationDidBecomeActive` и через секунду после показа; журнал пишет `moved by the system` и `put back`
- Поведение окон проверять запуском через Finder или Dock (`osascript -e 'tell application "Finder" to open POSIX file …'`), а где причину не видно — сначала журнал размещения, потом правка
