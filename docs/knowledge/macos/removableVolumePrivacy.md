# macOS: доступ приложения к съёмному тому

Наблюдалось 2026-09-25 на macOS 26.6.2: тест внутри приложения повисал, запуская тестовый RDP-сервер.
Разбор — по архиву системного журнала из результатов теста; зависание 2026-09-24 по признакам то же, но журнала от него не осталось.

## Дочерний процесс спрашивает от имени приложения

**Суть:**
- Тест внутри приложения запускал `sfreerdp-server` с тома `/Volumes/Storage`, а macOS считает этот том съёмным
- В момент запуска `tccd` получил от `sandboxd` запрос службы `kTCCServiceSystemPolicyRemovableVolumes`: «ответственный» — приложение VibeRDP, «обращающийся» — сервер
- Следом в журнале `Failed to match existing code requirement for subject tech.vibebrains.viberdp` и `AUTHREQ_PROMPTING`: на экране появился системный вопрос о доступе к файлам на съёмном томе
- Пока вопрос не отвечен, запуск процесса не завершается: главный поток теста стоял в `Process.run()`, движок не написал ни строки, собственный предел ожидания теста не сработал
- Сервер открыл сокет через 101 с после старта процесса — _чем кончился вопрос, журнал не показывает: архив обрывается там, где тест сняли по пределу_
- Разрешение привязано к требованию подписи, а ad-hoc подпись меняется с каждой сборкой: после пересборки вопрос возникает снова, а сборка без изменений проходит молча — так вчерашняя сборка утром прошла, а свежая повисла
- На раннере CI кэш лежит на системном диске, и вопроса там нет

**Применение:**
- Внешние процессы для тестов запускает скрипт сборки `build-client.sh`, а не код внутри приложения: у скрипта доступ терминала, из которого его запустили
- Тесту внутри приложения достаётся только то, что лежит вне съёмного тома: путь сокета во временной папке
- Продукта это касается напрямую: когда приложение начнёт читать файлы пользователя (задачи 2.4 и 3.5), для съёмного тома macOS спросит пользователя — это ожидаемо, а с подписью Developer ID (задача 8.4) ответ переживёт обновление
- Похожая задержка на системной проверке уже встречалась с локальной сетью — [localNetworkPrivacy.md](localNetworkPrivacy.md)

## Как это находится

**Суть:**
- Финализированный xcresult кладёт в диагностику архив системного журнала сессии тестов, `test-session-systemlogs-….logarchive`, около 100 МБ; достаёт его `xcrun xcresulttool export diagnostics`
- Бандл, чей xcodebuild убили снаружи, не финализирован: архива нет, остаются только журналы в `Staging` — поэтому у тестов свой предел, см. [xcodeClient.md](xcodeClient.md)
- Читает архив `/usr/bin/log show <архив> --predicate 'process == "tccd"'`; в zsh `log` — встроенная команда, и без полного пути вывод пустой
- Процесс, повисший на запуске, выдаёт время: `ps -o lstart -p <pid>` против времени создания сокета `stat -f %SB <файл>`

**Источники:**
- Архив журнала из `test-arm64.xcresult` прогона 2026-09-25 08:40: запросы `msgID=162.567` и `162.568`
- `client-macos/scripts/build-client.sh`, функции `start_test_server` и `stop_test_server`
