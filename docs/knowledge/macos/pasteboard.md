# macOS: буфер обмена для моста с удалённым компьютером

Проверено 2026-09-25 на macOS 26.6.2, задача 2.1; мост — `client-macos/Clipboard/ClipboardBridge.swift`, тесты — `ClipboardBridgeTests` и `LiveServerTests.testClipboardRoundTrip`.
Протокол с другой стороны — [rdp/clipboard.md](../rdp/clipboard.md), приватность — [pasteboardPrivacy.md](pasteboardPrivacy.md).

## Изменения буфера видны только по счётчику

**Суть:**
- У `NSPasteboard` нет события «содержимое изменилось»: есть только `changeCount`, и его надо читать самому
- `clearContents()` увеличивает счётчик; запись нового содержимого после неё — нет
- Таймер в режимах `.common` работает и пока открыто меню, в обычном режиме — нет

**Применение:** мост читает счётчик каждые 250 мс, пока идёт сессия; своё изменение — элемент для буфера удалённого компьютера — он запоминает по счётчику и не отправляет обратно.

## Данные по запросу

**Суть:**
- `NSPasteboardItem` с `NSPasteboardItemDataProvider` объявляет типы без данных; данные просит `pasteboard(_:item:provideDataForType:)`, когда кто-то вставляет
- Провайдер вызывается на главном потоке: чужое приложение вставляет через цикл событий, своё — прямо внутри чтения
- Провайдер обязан ответить синхронно: мост ждёт данные удалённого компьютера до 10 секунд, и главный поток всё это время стоит
- Данные, которые никто не успел попросить, пропадают вместе с провайдером

**Применение:** когда сессия кончается, мост убирает свой элемент из буфера, если он ещё текущий: наполнить его больше нечем.

## Тесты не трогают буфер пользователя

**Суть:**
- `NSPasteboard(name:)` с уникальным именем — отдельный буфер со всей механикой общего: счётчиком, элементами и провайдерами
- `releaseGlobally()` освобождает его после теста

**Применение:** тесты моста и живой тест с сервером-эхо идут на частном буфере; общий буфер этого Мака тестами не читается и не пишется.

## Swift 6: провайдер на главном акторе

**Суть:**
- Методы `NSPasteboardItemDataProvider` в SDK не привязаны к главному актору, а мост — `@MainActor`
- `MainActor.assumeIsolated` внутри `nonisolated` метода не собирается: `NSPasteboardItem` не `Sendable`, и Swift 6 видит гонку при передаче
- Работает изолированное соответствие `extension ClipboardBridge: @MainActor NSPasteboardItemDataProvider` — но только с явным `@MainActor` на самих методах: без него компилятор выводит их неизолированными

**Применение:** так и сделано в `ClipboardBridge.swift`.
