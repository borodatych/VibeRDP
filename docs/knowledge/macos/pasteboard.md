# macOS: буфер обмена для моста с удалённым компьютером

Проверено 2026-09-25 на macOS 26.6.2, задача 2.1; мост — `client-macos/Clipboard/ClipboardBridge.swift`, тесты — `ClipboardBridgeTests` и `LiveServerTests.testClipboardRoundTrip`.
Протокол с другой стороны — [rdp/clipboard.md](../rdp/clipboard.md), приватность — [pasteboardPrivacy.md](pasteboardPrivacy.md).

## Изменения буфера видны только по счётчику

**Суть:**
- У `NSPasteboard` нет события «содержимое изменилось»: есть только `changeCount`, и его надо читать самому
- `clearContents()` увеличивает счётчик; запись нового содержимого после неё — нет
- Таймер в режимах `.common` работает и пока открыто меню, в обычном режиме — нет

**Применение:** мост читает счётчик каждые 250 мс, пока идёт сессия; своё изменение — элемент для буфера удалённого компьютера — он запоминает по счётчику и не отправляет обратно.

## Данные по запросу

**Суть:**
- `NSPasteboardItem` с `NSPasteboardItemDataProvider` объявляет типы без данных; данные просит `pasteboard(_:item:provideDataForType:)`, когда кто-то вставляет
- Провайдер вызывается на главном потоке: чужое приложение вставляет через цикл событий, своё — прямо внутри чтения
- Провайдер обязан ответить синхронно: мост ждёт данные удалённого компьютера до 10 секунд, и главный поток всё это время стоит
- Данные, которые никто не успел попросить, пропадают вместе с провайдером

**Применение:** когда сессия кончается, мост убирает свой элемент из буфера, если он ещё текущий: наполнить его больше нечем.

## HTML для Мака объявляет свою кодировку

**Суть:**
- `NSAttributedString` читает HTML без объявленной кодировки как Latin-1: «<p>Привет</p>» в UTF-8 превращается в «РџСЂРёРІРµС‚», а с `<meta charset="utf-8">` в начале читается верно — проверено пробой на macOS 26.6.2
- Так HTML вставляют TextEdit и другие программы на тексте AppKit
- HTML на Маке — UTF-8 как правило; записанный в UTF-16 начинается с метки порядка байтов

**Применение:** мост ставит `<meta charset="utf-8">` перед HTML с Windows — он всегда UTF-8; первое объявление побеждает; HTML Мака в UTF-16 переводится в UTF-8 до ядра.

## Картинки: PNG и TIFF

**Суть:**
- Снимки экрана и браузеры кладут в буфер PNG, большинство программ AppKit — только TIFF (`public.tiff`)
- Программа, вставляющая картинку, может спросить и PNG, и TIFF — провайдер элемента получит два вопроса
- `NSBitmapImageRep.colorAt` отдаёт цвет в калиброванном пространстве, и перевод в sRGB сдвигает цвета даже у картинки с профилем sRGB: чистый красный становится `1, 0.149, 0` — проверено пробой на macOS 26.6.2
- Точное сравнение пикселей — отрисовкой в `CGContext` с пространством sRGB

**Применение:** мост предлагает картинку, если в буфере есть PNG или TIFF, и отдаёт ядру PNG, TIFF перекладывая через `NSBitmapImageRep`; картинка с Windows стоит на Маке как PNG и TIFF, приходит с сервера один раз на оба типа; тесты сравнивают пиксели через `CGContext`.

## Файлы: Finder вставляет только существующие

**Суть:**
- Finder вставляет из буфера файлы по ссылкам `public.file-url`, по одной ссылке на элемент буфера
- Обещание файла (`NSFilePromiseProvider`) работает при перетаскивании, а вставку из буфера Finder не выполняет: на форуме Apple разработчики сообщают, что метод записи файла так и не вызывается; ответа Apple нет — [форум Apple](https://developer.apple.com/forums/thread/683081)
- Ссылку можно отдать лениво, провайдером данных, но к её выдаче файл должен существовать
- Менеджеры буфера обмена читают данные сразу после копирования — ленивая ссылка сработает и для них

**Применение:** мост ставит на Мак по элементу на каждое имя верхнего уровня копии Windows; первая вставка тянет все файлы во временную папку в кэше приложения, пока вставка ждёт, а каждый элемент отдаёт ссылку на своё; папка удаляется при следующем копировании в Windows и в конце сессии, забытые — через сутки.

## Ожидание на главном потоке: вложенный цикл не выполняет главную очередь

**Суть:**
- Провайдер данных отвечает синхронно, на главном потоке; копия файлов идёт минуты, и ожидание — модальное окно с таймером в режиме `.modalPanel`
- Если вставка вызвана из блока главной очереди — задачи главного актора или `DispatchQueue.main.async`, — вложенный цикл не выполняет главную очередь снова: завершение копии, присланное через `Task { @MainActor }`, не приходит никогда — поймано зависанием живого теста на минуту
- Таймеры и источники цикла во вложенном цикле работают; `abortModal` завершает модальный цикл из таймера, `stopModal` — только из события

**Применение:** поток копии пишет итог в общий объект прогресса под замком, таймер модального окна видит итог и зовёт `abortModal`; окно становится видимым через полсекунды, так короткая копия проходит без мелькания.

## Тесты не трогают буфер пользователя

**Суть:**
- `NSPasteboard(name:)` с уникальным именем — отдельный буфер со всей механикой общего: счётчиком, элементами и провайдерами
- `releaseGlobally()` освобождает его после теста

**Применение:** тесты моста и живой тест с сервером-эхо идут на частном буфере; общий буфер этого Мака тестами не читается и не пишется.

## Swift 6: провайдер на главном акторе

**Суть:**
- Методы `NSPasteboardItemDataProvider` в SDK не привязаны к главному актору, а мост — `@MainActor`
- `MainActor.assumeIsolated` внутри `nonisolated` метода не собирается: `NSPasteboardItem` не `Sendable`, и Swift 6 видит гонку при передаче
- Работает изолированное соответствие `extension ClipboardBridge: @MainActor NSPasteboardItemDataProvider` — но только с явным `@MainActor` на самих методах: без него компилятор выводит их неизолированными

**Применение:** так и сделано в `ClipboardBridge.swift`.
