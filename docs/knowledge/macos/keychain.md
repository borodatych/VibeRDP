# macOS: пароли профилей в связке ключей

Проверено 2026-09-25 на macOS 26, задача 1.5; тест — `KeychainPasswordStoreTests`.
Реализация — `client-macos/Connections/PasswordStore.swift`, решение 18 в [decisions.md](../../decisions.md).

## Какая связка ключей доступна приложению с ad-hoc подписью

**Суть:**
- Защищённой связке ключей (`kSecUseDataProtectionKeychain`) нужен подписанный идентификатор приложения — entitlement `application-identifier` или `keychain-access-groups`; у бинаря с ad-hoc подписью их нет, и она отвечает `errSecMissingEntitlement` (-34018) — проверено пробой: `SecItemAdd` с `kSecUseDataProtectionKeychain`
- Файловая связка входа работает без entitlement: запись класса `kSecClassGenericPassword` получает список доступа с приложением, которое её создало
- Приложение с ad-hoc подписью меняет подпись при каждой сборке, поэтому другая сборка при первом чтении пароля показывает системный вопрос о доступе к связке; «Разрешать всегда» снимает его до следующей сборки
- Проверка наличия записи с `kSecReturnAttributes` пароль не расшифровывает и вопроса не вызывает
- Тесты внутри приложения создают и читают запись в одном процессе — вопроса нет; своя служба на каждый прогон и удаление в `tearDown` не оставляют следов в связке владельца

**Применение:**
- Пароль профиля — generic password: служба `tech.vibebrains.viberdp.connection`, учётная запись — id профиля, подпись в «Связке ключей» — «VibeRDP: <имя подключения>»
- Список подключений узнаёт о сохранённом пароле без чтения секрета; сам пароль читается только при подключении
- Подпись Developer ID (задача 8.4) закрепит подпись приложения, и вопрос после обновления уйдёт

**Не проверено:** поведение на раннере CI — там тест связки ключей пройдёт при первом пуше.
