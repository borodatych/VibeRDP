# SWIFT НОВЕЕ СИСТЕМЫ: ЧТО ЛОВИТ ПРОВЕРКА БАНДЛА

## 1. В чём дело

Компилятор Xcode 27 знает возможности языка, которым нужен рантайм Swift новее macOS 14
Сборка с `MACOSX_DEPLOYMENT_TARGET=14.0` их не запрещает: символ уходит в бинарь слабой ссылкой, и на macOS 14 вызов упадёт
Скрипт клиента ловит такие символы проверкой бандла: сообщение `uses APIs newer than macOS 14.0` с именем символа

## 2. Встреченные символы

- `_swift_willThrowTypedImpl` — типизированный `throws(Ошибка)`: заменён обычным `throws`, тип ошибки проверяется в месте вызова
- `_swift_coroFrameAlloc` — изменение значения словаря на месте, например `windows[id]?.icon = png`: компилятор делает сопрограмму `modify` у `Dictionary`; заменено чтением значения и записью обратно

## 3. Как искать источник

Символ называет не файл, а рантайм; файл находится по объектным файлам сборки:
`nm -u` по `.o` в `DerivedData/…/Objects-normal/arm64` — какой ссылается на символ
Функцию внутри — `objdump -d -r` и `swift-demangle`
Специализация могла осесть в чужом объектном файле: у `_swift_coroFrameAlloc` это был `SeamLink.o`, а запись — в `RemoteWindows.swift`
