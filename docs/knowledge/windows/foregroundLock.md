# ФОКУС ИЗ ФОНОВОГО ПРОЦЕССА

## 1. Почему SetForegroundWindow отказывает хелперу

Windows отдаёт передний план только процессу, который получил последний ввод, или тому, кому такой процесс разрешил
Хелпер ввода не получает никогда: пользователь работает в окнах приложений, а команду `activate` приносит канал
Поэтому голый `SetForegroundWindow` из хелпера возвращает 0 и лишь мигает кнопкой на панели задач

## 2. Что делает хелпер

На время вызова хелпер присоединяет свой ввод к потоку текущего переднего окна через `AttachThreadInput`
Затем вызывает `BringWindowToTop` и `SetForegroundWindow` и отсоединяется на любом исходе
Свёрнутое окно сначала восстанавливается через `ShowWindow(SW_RESTORE)`
Отказ всё равно возможен, он уходит клиенту ошибкой `denied`, а не молчанием

## 3. Остальные команды

`minimize`, `maximize`, `restore` и `close` отправляются через `PostMessage`, а не `SendMessage`: зависшее окно не держит хелпер
`move` пересчитывает видимые границы во внешний прямоугольник: невидимая рамка изменения размера и тень остаются вокруг цели (`outer_rect` в `desktop.rs`)

Код — `helper-win/src/commands.rs`
_Живьём на Windows ещё не проверено_
