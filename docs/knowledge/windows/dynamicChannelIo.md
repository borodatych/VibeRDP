# ДИНАМИЧЕСКИЙ КАНАЛ СО СТОРОНЫ СЕРВЕРА

## 1. Как читать и писать

`WTSVirtualChannelOpenEx` с `WTS_CHANNEL_OPTION_DYNAMIC` отдаёт дескриптор канала
Для динамического канала Microsoft документирует и показывает в образце DVC другой путь — файловый дескриптор: `WTSVirtualChannelQuery(…, WTSVirtualFileHandle, …)`, затем `ReadFile` и `WriteFile`
Дескриптор открыт для перекрытого ввода-вывода: вызовы без `OVERLAPPED` с событием ведут себя непредсказуемо

## 2. Что приходит в чтении

Каждое чтение отдаёт `CHANNEL_PDU_HEADER` (8 байт: полная длина сообщения и флаги) и за ним кусок потока до `CHANNEL_CHUNK_LENGTH` (1600) байт
Заголовок надо срезать, иначе он попадёт в сборщик кадров и сломает длину
Границы кусков не совпадают с границами наших кадров — кадр собирается по своей длине (`FrameReader`)

## 3. Жизнь дескрипторов

Файловый дескриптор лежит в памяти, которую возвращает запрос; её освобождают `WTSFreeMemory`, поэтому дескриптор сперва дублируется
Ошибку `DuplicateHandle` брать до `WTSFreeMemory` — освобождение может переписать последнюю ошибку
Пока у клиента нет слушателя канала, `WTSVirtualChannelOpenEx` возвращает NULL: для хелпера это обычное состояние, он повторяет попытку с растущей паузой

Код — `helper-win/src/channel.rs`
