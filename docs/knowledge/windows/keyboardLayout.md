# Windows: раскладка чужого окна

## `ActivateKeyboardLayout` не переключает раскладку другому процессу

**Контекст:** вариант Б синхронизации раскладки в [idea.md](../../idea.md) §3.2; задача 3.3.

**Суть:**
- `ActivateKeyboardLayout` задаёт раскладку вызывающему потоку или текущему процессу; в разделе Remarks сказано прямо: функция влияет только на свой процесс или поток
- Флаг `KLF_SETFORPROCESS` расширяет действие на весь процесс вызывающего — но только на него
- `WM_INPUTLANGCHANGEREQUEST` (0x0050) приходит окну с фокусом, когда пользователь выбирает новый язык ввода; в `lParam` — идентификатор раскладки (HKL)
- Приложение принимает смену, передав сообщение в `DefWindowProc`: тот активирует раскладку и шлёт `WM_INPUTLANGCHANGE`; отказаться можно, вернув управление без `DefWindowProc`

**Применение:**
- Вариант Б в §3.2 («хелпер вызывает `ActivateKeyboardLayout` для foreground-окна») так не сработает: хелпер сменит раскладку только себе
- Рабочий механизм варианта Б: хелпер отправляет `WM_INPUTLANGCHANGEREQUEST` с нужным HKL окну с фокусом
- Замер на 3.3 должен включать приложения, которые вправе отказаться от смены

**Не проверено:**
- Доходит ли сообщение от хелпера до окон процессов с повышенными правами — ожидаемо нет из-за изоляции уровней целостности (UIPI)
- Кому слать: foreground-окну или окну с фокусом внутри него (`GetGUIThreadInfo`)
