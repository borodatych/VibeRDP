- [keyboardInput.md](freerdp/keyboardInput.md) — клавиатура: скан-код набора 1 с битом `KBDEXT`, флаги нажатия и повтора ставит `freerdp_input_send_keyboard_event_ex`, Pause — последовательностью mstsc; фокус — Tab up, синхронизация Lock-клавиш, Tab up; FreeRDP не помнит нажатых клавиш, их помнит ядро; таблица winpr для Мака путает правый ⌃ и fn с Win; клавиша G интерактивного sample-сервера для живого теста
- [pointerInput.md](freerdp/pointerInput.md) — мышь и курсор: `freerdp_connect` возвращается до ACTIVE, общий помощник выбрасывает ввод вне ACTIVE, асинхронной очереди в FreeRDP 3 нет — у ядра своя, на потоке сессии; 9-битное колесо, горизонтальное и боковые кнопки — по возможностям сервера; курсор из масок — прямая альфа, шахматка вместо инверсии, неудача `Pointer_New` роняет пакет
- [h264.md](freerdp/h264.md) — H.264 в RDPGFX: подсистемы декодера FreeRDP задаются при компиляции — свой декодер на VideoToolbox вписан патчем к копии подмодуля; Annex B в описание формата и сэмплы с длинами, синхронное декодирование, пересоздание сессии после сна; родной NV12 и своя копия в I420 с запасом под чтение векторами; дефект SSE-сборки AVC444 v1 во FreeRDP и его патч; проверка кодером VideoToolbox через API FreeRDP без Windows
- [kerberos.md](freerdp/kerberos.md) — Kerberos в NLA: SSP FreeRDP зовёт krb5, а не GSSAPI, прослойку `Kerberos.framework` он отвергает — своя MIT 1.22.2 статически; проверка подписи релиза; статическая сборка: частичная установка, `-framework Kerberos` для кэша `API:`, дописанный `mit-krb5.pc` и `PKG_CONFIG_ARGN=--static`; слабая `_voucher_mach_msg_set` из заглушек mig; упаковка по 2 байта на x86_64 и отключённые chained fixups; модули поиска KDC из `KerberosFrameworkPlugins`; FreeRDP берёт кэш по умолчанию вместо найденного — у ядра свой кэш в памяти на сессию; прокси KDC FreeRDP применяет только к первичному билету; тестовая область с KDC и sample-сервером на keytab
- [credentials.md](freerdp/credentials.md) — вопрос об учётных данных: когда `AuthenticateEx` спрашивает над NLA, TLS и шлюзом, что значат FALSE и пустой ответ, слоты настроек и повтор внутри `freerdp_connect`; после неверного пароля FreeRDP не повторяет — повтор делает приложение новой сессией
- [reconnection.md](freerdp/reconnection.md) — переподключение: `client_auto_reconnect_ex` восстанавливает только обрыв сети без Error Info и без проблем учётных данных; `RetryDialog` задаёт паузу, `window_events` — выход; FreeRDP сбрасывает событие прерывания перед попыткой; GDI переживает переподключение; keepalive и Refresh Rect после сна; обрыв для теста — `freerdp_peer_disconnect`
- [diagnosticsLog.md](freerdp/diagnosticsLog.md) — журнал WLog в файл: приёмник корня `WLOG_APPENDER_FILE` с `outputfilepath` и `outputfilename`, уровень у корня; консольный приёмник пишет INFO в stdout, WARN и выше в stderr — у приложения из Finder журнал движка терялся; строки приложения под своими тегами в том же файле
- [displayControl.md](freerdp/displayControl.md) — размер стола через Display Control: возможности сервера приходят первыми, стороны 200–8192, ширина чётная; ответ — сброс графики RDPGFX; по живому Windows 2351×1286 стал 2350×1286
- [channelChunks.md](freerdp/channelChunks.md) — дефект FreeRDP 3.32.0: сообщение статического канала больше 1600 байт даёт `read error` 1359 и рвёт сессию — буфер по первому куску, ёмкость с округлением сравнивается с длиной; исправление upstream `190167212` наложено патчем; после такой ошибки живая Windows отвечает на переподключение `ERRINFO_RPC_INITIATED_DISCONNECT`
- [clientLifecycle.md](freerdp/clientLifecycle.md) — жизненный цикл клиента в ядре: поток сессии по образцу Mac-клиента, прерывание на любом этапе, отмена отличима от сбоя, RDP8-функции тянут rdpdr и rdpsnd, консольные колбэки клиентской библиотеки читают stdin; внешняя проверка сертификата идёт после рукопожатия, и отказ по коду неотличим от сбоя TLS; повтор подключения после обрыва; разбор `DOMAIN\user`, категории ошибок; звук: rdpsnd тянет rdpdr, подсистема `mac` только с `WITH_MACAUDIO`, вывод AudioQueue в PCM

## rdp

- [clipboard.md](rdp/clipboard.md) — CLIPRDR: обмен начинает Monitor Ready, стороны объявляют форматы, данные идут при вставке; ответы без номера — по одному вопросу, поздний ответ выбрасывается; пустой список сервера FreeRDP до клиента не доносит; `CF_UNICODETEXT` и CRLF ⇄ UTF-8 и LF; HTML и RTF — зарегистрированные форматы по имени, заголовок «HTML Format» со смещениями в байтах; картинки — «PNG», `CF_DIBV5` и `CF_DIB`, растр читает ImageIO с приставленным заголовком файла, изображение ImageIO ленивое и держит данные; файлы — «FileGroupDescriptorW» и вопросы о содержимом с номером, длина ответа — в `cbRequested`, проверка имён сервера; сервер-эхо для тестов; живая Windows отклоняет второй подряд список Мака ответом `CB_RESPONSE_FAIL`, клиенты FreeRDP ответ на список не читают — ядро повторяет отклонённый список, и Windows принимает его с первого повтора

- [railSession.md](rdp/railSession.md) — RemoteApp заказывается флагом `INFO_RAIL` при подключении: откат RAIL → Seam/Desktop только переподключением, RAIL пробуется лишь при включении в профиле
