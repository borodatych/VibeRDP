# FreeRDP: размер рабочего стола через Display Control

Сверено по исходникам FreeRDP 3.32.0 и журналам живой проверки на Windows — 2026-09-26, задача 3.1 (решение 35).
Реализация — `core/src/display.c`; тесты — `core/tests/displayTests.c`, `client-macos/Tests/SessionWindowTests.swift`.

## Канал и его ограничения

**Суть:**
- Канал `Microsoft::Windows::RDS::DisplayControl` — динамический, FreeRDP грузит его как `disp` вместе с RDPGFX; в журнале движка это строка `Loading Dynamic Virtual Channel disp`
- Сервер первым шлёт возможности, клиент получает их колбэком `DisplayControlCaps`; раскладка мониторов до этого не отправляется — запрос размера ждёт возможностей
- Размеры одного монитора — от 200 до 8192 по обеим сторонам (`include/freerdp/channels/disp.h:37-41`), ширина по MS-RDPEDISP не может быть нечётной
- Ответ сервера — не отдельное сообщение, а сброс графики RDPGFX с новым размером: тот же путь, что при смене разрешения самим сервером, и поверхность клиента пересоздаётся
- Живая проверка 2026-09-25 и 2026-09-26 (Windows в домене): запрос 2351×1286 дал стол 2350×1286, запрос 3008×1942 — 3008×1942

**Применение:**
- Ядро приводит размер к пределам и к чётной ширине, округляя вниз: стол остаётся внутри окна
- Шлётся только новый размер: тот, с которым стол уже открыт, считается отправленным при подключении канала
- Запрос идёт очередью ввода на потоке сессии, возможности приходят на потоке канала — состояние под мьютексом
- Приложение шлёт размер после 0,3 с без изменений окна, чтобы сервер не перерисовывал стол на каждом шаге перетаскивания
- Размер — в точках окна: на Retina стол растянут вдвое; `DesktopScaleFactor` и пиксели дисплея — задача 3.2
