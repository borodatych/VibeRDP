# СВОЙ ДИНАМИЧЕСКИЙ КАНАЛ В КЛИЕНТЕ

## 1. Как FreeRDP находит аддин по имени

Канал `drdynvc` грузит каждый динамический канал из списка настроек по имени: `freerdp_load_channel_addin_entry(имя, NULL, NULL, FREERDP_ADDIN_CHANNEL_DYNAMIC)`
Имя сначала спрашивается у поставщика, которого ставит `freerdp_register_addin_provider`, потом у загрузчика разделяемых библиотек
Поставщик один на процесс, а `freerdp_client_context_new` при каждом создании контекста ставит заново свой — `freerdp_channels_load_static_addin_entry`

## 2. Что делает ядро

Перед каждым подключением ядро ставит своего поставщика: имя `vibeseam` он отдаёт сам, остальные передаёт поставщику FreeRDP
Канал добавляется в настройки через `freerdp_client_add_dynamic_channel` — имя в списке и есть имя, по которому спрашивают поставщика
Поставщик без состояния, поэтому общий на процесс не мешает нескольким сессиям
Плагин собран на `freerdp_generic_DVCPluginEntry`: FreeRDP сам создаёт слушателя канала `VibeSeam` и зовёт `OnOpen`, `OnDataReceived`, `OnClose`
Свою сессию плагин находит через `rdpContext` в `initPlugin`: контекст клиента и есть начало `VRCSession`

## 3. Грабли

- Точка входа приводится к `PVIRTUALCHANNELENTRY` через `WINPR_FUNC_PTR_CAST` только из переменной указателя: имя функции макрос не принимает, сборка падает на статической проверке размера
- `OnClose` освобождает колбэк канала сам: общий слушатель выделил его под этот канал и дальше не трогает
- Колбэки канала идут в потоке каналов движка; запись из потоков приложения защищена мьютексом, чтобы канал не закрылся посреди `Write`

Код — `core/src/seam.c`
Проверено сборкой, тестами ядра с подменным каналом и живым тестом клиента на тестовом сервере: остальные каналы грузятся как раньше
