## 1. Что строим

**VibeRDP** — open-source RDP-клиент для macOS, который заменяет Microsoft Windows App и решает две его главные боли:

1. **Буфер обмена, который работает.** В Windows App скопированное на Маке часто не доходит до Windows: уходит предыдущее содержимое, пока не переключишь фокус туда-обратно. Причина в том, что у macOS нет события «буфер изменился», а клиент проверяет `NSPasteboard.changeCount` только при смене фокуса. VibeRDP опрашивает буфер постоянно и анонсирует изменения сразу.
2. **Независимые окна (seamless-режим).** Окна Windows-приложений открываются как отдельные нативные окна macOS: у каждого своё место в Mission Control, Cmd+Tab, своя иконка. Так работают Parallels Coherence и VMware Unity, только здесь поверх обычного RDP к рабочей машине.

### Три режима работы (выбираются автоматически, в порядке приоритета)

| Режим | Когда | Как |
|---|---|---|
| **RAIL** (RemoteApp) | На хосте разрешён RemoteApp (нужен ключ HKLM, т.е. админ) | Нативный RAIL-канал RDP, реализация FreeRDP |
| **Seam** | На хосте запущен `vibe-seam-helper` (без админа и без HKLM) | Свой Dynamic Virtual Channel: хелпер шлёт список окон и геометрию, клиент вырезает регионы из фреймбуфера в отдельные `NSWindow` |
| **Desktop** | Ни то, ни другое | Обычный полноэкранный/оконный рабочий стол, но с нормальным буфером |

Fallback должен быть незаметным: при подключении клиент ждёт `HELLO` от хелпера (таймаут ~2 с). Если ответа нет, клиент остаётся в Desktop и не показывает ошибок. Прецедент архитектуры Seam — SeamlessRDP из rdesktop (`seamlessrdpshell.exe` + виртуальный канал).

### Целевая аудитория
- Разработчики и офисники на Маке, которым нужна рабочая Windows-машина по RDP.
- Корпоративные среды без админских прав на рабочей машине (ключевой кейс — Seam-режим без реестра HKLM).

### Не цели (на старте)
- Windows- и Linux-клиенты (архитектура не должна им мешать, но пишем под macOS).
- Проброс USB, принтеров, смарт-карт.
- Собственный сервер или релей: всё идёт внутри RDP-сессии.

## 2. Стек и архитектурные решения

| Компонент | Технология | Почему |
|---|---|---|
| RDP-ядро | **FreeRDP 3.x** (C, Apache-2.0), git submodule, сборка CMake, universal binary arm64+x86_64 | Зрелая реализация: NLA/CredSSP, RD Gateway, RDPGFX/H.264, CLIPRDR, RAIL, DVC-аддины |
| Мост к ядру | `VibeRDPCore` — тонкая C-обёртка над libfreerdp с плоским API для Swift | Изолирует Swift от внутренностей FreeRDP |
| macOS-клиент | **Swift 5.10+, AppKit + Metal**; SwiftUI только для настроек и списка подключений | Нужны настоящие отдельные `NSWindow` с низколатентным выводом текстур. WebView (Tauri) здесь не подходит: гонять фреймбуфер через IPC дорого, нативный мультиоконный контроль хуже |
| Проект Xcode | Генерация через **XcodeGen** (`project.yml` в репо, `.xcodeproj` в `.gitignore`) | Никаких конфликтов в pbxproj |
| Хост-хелпер | **Rust** (`windows-rs`), один `.exe` без зависимостей, target `x86_64-pc-windows-msvc` | Без .NET-рантайма, маленький, запускается от обычного пользователя |
| Протокол Seam | Бинарные фреймы: `u32 length` + MessagePack; версионирование в `HELLO` | Компактно, есть библиотеки и на Swift, и на Rust |
| Секреты | macOS Keychain | Никаких паролей в файлах |
| Автообновление | Sparkle 2 | Стандарт для macOS вне App Store |
| CI | GitHub Actions: macOS-раннер (клиент), Windows-раннер (хелпер) | |

> Решение «Swift + FreeRDP вместо Tauri» — осознанное отступление от дефолтного стека экосистемы. Если видишь фактическую причину пересмотреть его, подними возражение **до** выполнения.

## 3. Ключевые технические детали

### 3.1 Буфер обмена (CLIPRDR)
- **Mac → Win:** таймер опроса `NSPasteboard.general.changeCount` каждые 250 мс (при активной сессии). На изменение отправляется Format List PDU с доступными форматами. Данные отдаются только по Format Data Request (delayed rendering).
- **Win → Mac:** на Format List PDU кладём в `NSPasteboard` элементы с `NSPasteboardItemDataProvider` и запрашиваем данные лениво, когда macOS их реально попросит.
- **Защита от эха:** после записи в пасборд запоминаем свой `changeCount` и не анонсируем его обратно.
- **Форматы по этапам:** текст (`CF_UNICODETEXT` ⇄ `public.utf8-plain-text`) → HTML/RTF → изображения (`CF_DIB`/PNG ⇄ `public.png`/`public.tiff`) → файлы (`FileGroupDescriptorW` + File Contents Request ⇄ file promises).
- Переводы строк: `\r\n` ⇄ `\n`.

### 3.2 Клавиатура
- Маппинг Cmd→Ctrl для стандартных сочетаний (настраиваемый), Option→Alt.
- **Синхронизация раскладки RU/EN.** Это отдельная боль Windows App. Вариант А: режим Unicode-ввода (Unicode Keyboard Event). Вариант Б (при наличии хелпера): хелпер вызывает `ActivateKeyboardLayout` для foreground-окна при смене раскладки на Маке. Выбор делается на этапе, где это реализуется, с замером.

### 3.3 Seam-режим
**Хелпер (Windows, user-level):**
- Открывает DVC: `WTSVirtualChannelOpenEx(WTS_CURRENT_SESSION, "VibeSeam", WTS_CHANNEL_OPTION_DYNAMIC)`. Админ не нужен.
- Отслеживает окна: `SetWinEventHook` (CREATE/DESTROY/SHOW/HIDE/LOCATIONCHANGE/NAMECHANGE, `EVENT_SYSTEM_FOREGROUND`, MINIMIZESTART/END) плюс начальный `EnumWindows`.
- Точные границы окна — через `DwmGetWindowAttribute(DWMWA_EXTENDED_FRAME_BOUNDS)`, без невидимых теневых рамок.
- Фильтр окон: видимые top-level, не cloaked (`DWMWA_CLOAKED`), без `Shell_TrayWnd`/`Progman`/`WorkerW`. Owned-попапы, меню и тултипы передаются со ссылкой на владельца.
- Передаёт заголовок, иконку (PNG), z-order, состояние (normal/min/max), PID и имя exe.
- Исполняет команды клиента: activate, move/resize (`SetWindowPos`), minimize/maximize/restore/close (`WM_SYSCOMMAND`), а позже launch по ярлыку из меню «Пуск».
- Автозапуск без реестра HKLM: ярлык в `shell:startup` текущего пользователя. Установка — копированием exe, без инсталлятора с правами.
- Одна копия на сессию (named mutex). Если канал недоступен (не RDP-сессия), тихо ждёт и переподключается.

**Клиент (macOS):**
- Разрешение удалённой сессии равно объединению геометрии мониторов Мака с учётом Retina (DesktopScaleFactor, Display Control DVC). Координаты мапятся 1:1.
- Каждое удалённое окно — `NSWindow` без рамки (или с нативной рамкой, настраиваемо). Контент — субрегион общей Metal-текстуры фреймбуфера.
- Ввод из окна транслируется в глобальные координаты сессии.
- Перекрытия окон на хосте приводят к артефактам в вырезке, и это известное ограничение подхода. Смягчение: активация на Маке синхронизирует z-order на хосте, клиент поднимает на хосте окно, которое сейчас в фокусе.
- Иконки в Dock и Cmd+Tab — на этапе интеграции.

**Протокол** описывается и поддерживается в `protocol/seam-protocol.md` раньше любого кода, который его использует. Минимум сообщений: `HELLO{version, capabilities}`, `WINDOW_CREATE/UPDATE/DESTROY`, `WINDOW_ICON`, `Z_ORDER`, `FOREGROUND`, `CMD{window_id, action, args}`, `ACK/ERROR`, `PING/PONG`.

### 3.4 RAIL
- Перед подключением в Seam клиент пробует RAIL, если он включён в профиле. Если хост его не разрешил, клиент уходит в Seam или Desktop без ошибок для пользователя.
- В `docs/` добавить инструкцию для тех, у кого есть админ: как включить RemoteApp на Win10/11 Pro (`TSAppAllowList\fDisabledAllowList=1`).

### 3.5 Подключения
- Профили: хост, порт, пользователь, домен, RD Gateway, режим (auto/desktop/seam/rail), мониторы, маппинг клавиш.
- Импорт `.rdp`-файлов.
- NLA обязательно поддерживается; сертификаты сервера подтверждаются через диалог с запоминанием отпечатка.

## 4. Правила работы агента

- **Одна чекбокс-задача за итерацию.** Сделал, проверил, отметил `[x]`, коротко отчитался и остановился.
- **Возражение до выполнения.** О фактических и механических ошибках в задаче или спецификации говоришь до того, как писать код. Вкусовые решения оператора выполняешь без споров. После ответа на возражение выполняешь задачу один раз и к возражению не возвращаешься.
- **Автономия.** Самостоятельно принимаешь только решения, которые одновременно обратимы, некритичны и заменяемы через SOLID-абстракцию. Всё необратимое требует подтверждения оператора: удаление, смена лицензии, публикация релиза, смена протокола после v1.
- **Верификация.** Не выдумывай API FreeRDP, Win32 или AppKit. Сверяйся с исходниками submodule и документацией. Если не уверен, пиши об этом явно.
- **Тестирование на реальном хосте.** У агента нет Windows-машины. Всё, что требует живого подключения, помечай как «требует проверки оператором» и давай чек-лист шагов. Протокол Seam и логику менеджера окон покрывай unit-тестами с мок-каналом (Swift: XCTest, Rust: `cargo test`).
- **Раздел «Предложения»** в ROADMAP — для идей вне скоупа. Без команды оператора не реализуются.
- **knowledge.md** обновляй в конце каждого этапа: что сделано, решения, грабли, как собрать.
- Принципы: SOLID / DRY / KISS / YAGNI / fail-fast.
